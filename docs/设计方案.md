# ModStudio Electron：待确认的设计方案

状态：设计系统提案，尚未编写 Electron 前端实现。依据用户提供的 web-design-engineer skill，Checkpoint 1 需要先确认设计系统，之后才制作 v0；Checkpoint 2 需要展示并确认 v0，之后进入完整构建。

## 定位

- 角色：用于日常导入、预览、选择附件、修改贴图、AI 重绘和导出的桌面创作工作台。
- 观看距离：笔记本/桌面显示器，约 50–80 cm；以鼠标键盘操作为主。
- 氛围：沉静、精确，突出作品；用少量品牌蓝表达当前选择和主操作。
- 容量：基准 1440×960；适配 1280×800 及更大窗口，按空间收起检查器，画布优先。

## 设计系统

- 配色：石墨底 #181C23，面板 #222832，文字 #EAE8E2，品牌雾蓝 #8DB2E4。边框、次级文字和悬浮状态由这些颜色的明暗/透明度派生；警告不单靠颜色表达。
- 字体：Bahnschrift 用于品牌、标题和数值；Microsoft YaHei UI 用于中文界面。正文 16px，辅助文字 13–14px，区域标题 18–22px。
- 间距：4px 基准；常用 8/12/16/24/32px。
- 圆角：输入/按钮 6px；浮层 12px；主面板以分隔线和留白组织。
- 阴影：工作区以边框区分；仅弹窗、菜单使用克制的两级阴影。
- 动效：120–180ms，主要用于颜色和折叠；不对预览画布施加装饰动画，支持 reduced-motion。
- 品牌：沿用已有真实 app-icon；取消全屏主题插画叠底，让角色和贴图成为画面主体。

## 页面结构

1. 顶部：现有图标与 ModStudio、当前项目、导入、撤销/重做、保存、导出。
2. 左侧约 240px：资源与部件列表、搜索、缩略图、选择状态。
3. 中央弹性区域：大尺寸 Spine 画布；动画/皮肤选择、GPU 状态、适应窗口；底部播放控制、帧进度与缩放。
4. 右侧约 320px：上下文检查器，切换“部件”“贴图”“AI 重绘”；参数按实际选区逐步展开。
5. 底部状态行：素材路径、加载进度、未保存状态和实际运行状态。
6. 图集在中央区域与角色预览切换，或在宽屏时拆分显示，减少默认双画布争抢空间。

## Electron 迁移路线

- Electron 主进程负责窗口、原生目录选择、文件操作和任务调度；preload 通过 contextBridge 暴露逐项 IPC 方法，renderer 开启 contextIsolation/sandbox。
- React + TypeScript 组织界面，CSS 自定义属性承载上述 tokens；本地打包资源。
- 新画布采用 WebGL 绘制采样网格及贴图，适配浏览器 GPU；现有 WGL 实现不能直接放进 Chromium renderer，需要迁移对应着色与合成规则。
- 通过独立 .NET 服务桥逐步复用现有 Spine 骨骼解析、选区/遮罩、UV 回投和重绘提供方逻辑；前端不直接读取任意文件或执行任意命令。
- 原生 WinForms UI 不嵌进 Electron；其功能按工作流迁移到新前端。
- 验证覆盖真实 MOD 导入、播放、多选、图集定位、撤销、保存/导出；云端生成调用按用户已有授权和实际服务配置处理。

## 第一阶段 v0

确认设计系统后，先制作可查看的桌面工作台草稿，包含整体布局、配色、主交互和明确标记的占位状态；使用已有真实图标和本地参考素材，不伪造任务数据或模型生成结果。按 skill 展示 v0 并等待反馈后再连接完整工作流。

# Spine 贴图重绘实现说明

## 案例和产物

- 原素材位于 `F:\Neowiz\modder\test\原版内容 - 角色立绘 - char003793`。使用 `char003793.skel`、`char003793.atlas`、2048 × 1024 的 `char003793.png` 和同尺寸的 `char003793-skirt-mask.png`。骨骼版本为 Spine 4.1.11。
- [重绘流程 HTML](../../../docs/char003793-Spine贴图重绘流程.html) 包含两轮真实 GPT Image 的输入、原始输出与中英提示词、398 个三角形的双向坐标演示、第 4 页的动画对比和可下载图集。第 2、4 页分别存第一、二轮实际提示词。
- [排版记录](char003793-layout.json) 保存七块裙片的图集矩形、768 × 512 工作图矩形、少量邻近取样索引以及原始素材的 RGBA 校验值。七块裙片在本案例中的 atlas 区域均未旋转。
- 正向复现时保存一轮一份原始请求记录与原始输出。使用存档重放脚本时，脚本可导出这些图片及实际英文提示词，并从原图独立生成两轮图集。动画取样图和通过校验的取点来自存档，新请求需要重新计算或复核。

## 1. 冻结姿势和准备映射

用项目的 [Spine 加载和渲染入口](../../../renderer/spine-preview.js) 与 [图集兼容处理](../../../renderer/spine-compat.mjs) 读取同一 Skin 的动画和图集。对案例使用 `idle 0.00 s`。固定姿势后按 slot 绘制顺序取得每块当前附件、世界顶点、三角形索引及最终图集 UV。RegionAttachment 可拆成两个三角形，MeshAttachment 使用其现有三角形和变形后的世界顶点。UV 转像素时统一左上原点，使用对应图集页尺寸并处理 atlas 旋转及裁剪。

为每个目标图集像素记录图集页、附件与坐标。选中附件在图集的网格足迹、用户选区和原图有效 Alpha 相交得到候选集合 `C`。原矩形裁剪内可能有其他打包碎片，保留候选遮罩约束。若多个附件共享同一图集像素且需要不同颜色，先拆分共享区域再分别回写。

保存世界坐标到工作图的变换，把七块裙片单独渲染为 1024 × 1024 的工作图，再铺统一浅灰底。可额外渲染一张附件 ID 图与覆盖遮罩，供后续判断屏幕点的真实来源。保留裁切原点、比例、绘制顺序和每个三角形的两套坐标，避免后续截图缩放改变几何映射。

## 2. 重绘组装裙摆并按 UV 回写

把 1024 × 1024 组装工作图送入图像编辑工具。本案例目标是把淡紫色裙布改为低饱和青绿色。提示词约束轮廓、腰部开口、褶皱、荷叶边、画布与留白。画布分辨率变化时检查边界与内容是否仍对齐。若模型平移或局部拉伸了轮廓，先用稳定的轮廓点或接缝校正，偏移较大的区域重新生成或标为无效。

1. 对每个候选图集像素 `(x, y)` 取中心 `P = (x + 0.5, y + 0.5)`。在图集 UV 三角形中找到包含该点的三角形。解出满足 `P = aU₀ + bU₁ + cU₂` 且 `a + b + c = 1` 的重心权重，跳过退化三角形。
2. 用同样的权重对匹配的工作图顶点求 `Q = aS₀ + bS₁ + cS₂`。检查工作图点仍属于当前附件。被挡住、落在背景或输出缺少可信布料颜色时记为缺口。
3. 案例取色点记录为整数工作图像素索引 `(i,j)`。换算到生成图像素中心坐标，按 `g = (i + 0.5) × 输出宽 / 工作图宽 − 0.5` 计算 x，y 按各自高度同理。对四个邻近像素双线性取样，各 RGB 通道取整。
4. 把 RGB 写入原图集副本，记下集合 `W₁` 和实际取色索引。源和目的格点分开记录，以便复核几何位置与实际写入的区别。

实测取点可在 HTML 第 3 页选择 `skirt_r`。裙片内 `(65,137)` 对应图集像素 `(1912,564)`。取中心后，三角形内插值得到工作图坐标约 `(731.67,520.01)`。实际使用工作图像素 `(731,520)`，双线性取样中心约 `(895.30,636.91)`，写回 RGB `(165,196,182)`。原图 Alpha 为 `76`。

本轮七块都检查，共写入 **33,995** 个像素。 `skirt_l3` 在这一姿势中没有通过第一轮取样检查的像素，它的 **870** 个候选像素进入第二轮。

## 3. 在原尺寸 UV 补绘

1. 从第一轮图集取七块原尺寸矩形并平移到 768 × 512 灰底工作图。每块记录图集原点 `A`、工作图原点 `B` 和尺寸。图集像素 `P` 的工作图位置是 `B + (P − A)`。
2. 用同样的位移把 `C − W₁` 复制到独立的黑白 PNG，白色表示允许补绘。案例有 8,910 个白色像素。把三张图分别提交，顺序为**编辑目标、组装裙摆参考、黑白缺口图**。组装裙摆只提供布色、明暗、纹理和边饰参考，提示词要求按原工作图布局输出。
3. 案例原始输出为 1536 × 1024。按相同像素中心公式把工作图点换算到生成图。这里输出恰好是 2 倍，因此每个工作图格点对应的四个输出像素求均值并取整。布局发生移动时先校准相应裙片或把该片列入重绘。
4. 对每个白色缺口尝试使用同一位置通过验证的布料 RGB。边缘采不到可用颜色时，在同一裙片有效布料内找邻近样本，案例接受的最大偏移为 3 个工作图像素。找不到合格取样点就保留该图集点在第一轮后的状态，并记下坐标。
5. 仅在候选缺口的目标坐标写入 RGB。邻近样本只改变取色源，写回目的像素仍由遮罩和矩形定位。最终输出图集继续使用原始 Alpha，保持软透明边缘。

例如 `skirt_l3` 图集原点 `(945,346)`，工作图原点 `(621,85)`。裙片内像素 `(33,1)` 对应工作图 `(654,86)`，回写目标为图集 `(978,347)`。在生成图上，四个相邻位置的坐标组合是 x 取 `1308、1309`，y 取 `172、173`。它们的均值取整得到 `(169,197,181)`，回写后的 Alpha 仍为 `18`。

## 4. 复核与打包

- 逐像素验证选区外 RGBA 一致、全图 Alpha 一致、第一轮与第二轮目的坐标无重叠。回写率按 `(第一轮 + 第二轮) / 候选像素` 算。案例 8,317 直接补写、568 邻近补写、25 剩余。 `skirt_l1` 剩 2 个、`skirt_l4` 剩 23 个，精确坐标在脚本导出的 `reproduction.json`。
- 用新图集按相同姿势和骨骼渲染对照。案例第 4 页嵌入 4 秒 30 FPS 的同步 `idle` 对比，可切原图或第一轮为基准。滚轮以光标为中心缩放，放大后拖动平移，按到竖线时拖对比线。重点检查动作中露出的底层裙片和接缝。
- 缺口是未通过当前写回流程的像素。线性采样与透明叠加仍可能让它们参与画面。需要量化动画能可靠覆盖多少时，对每个采样时刻计算可写集合，按集合覆盖选择补帧。采样的并集才是该批帧可达到的上限。可见贡献和可靠写回是两项检查。见 [案例多帧覆盖分析](../../../docs/char003793-Spine动画多帧覆盖分析.html)。
- 交付原输入和输出 PNG、两轮提示词、候选及缺口遮罩、排版与写入索引、统计及最终图集。保留原骨骼与 atlas 的对应版本。图集文件名需要在替换时与 atlas 页名一致。
